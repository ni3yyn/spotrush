SPOTRUSH v46.1 — EOS setup error corrections

1. Back up your SpotRush project. Extract this overlay into the project root. Keep your 94 MB addons/epic-online-services-godot folder; do not replace it with a partial package.
2. Before opening Godot, run: python tools/patch_eosg_autoload_scope.py
3. Run .\tools\set_eos_client_secret.ps1. Enter your EOS Client Secret and your 64-character EOS Encryption Key at the hidden prompts. The exposed Client Secret should be rotated before any public release; never paste it into chat or commit it.
4. Run: python tools/verify_eos_install.py --platform both --require-local-config
5. Close and reopen Godot 4.7.2 so the EOSG source and autoload registry are reimported.
6. In Godot, use Project → Install Android Build Template… (the Godot 4.7.2 Gradle template command). This creates `android/build`, including `AndroidManifest.xml` and `build.gradle`.
7. Run: python tools/patch_android_template.py
8. Run: python tools/patch_eos_android_template.py

The EOSG source shim is idempotent and touches only addons/epic-online-services-godot/eos.gd. The Android scripts touch only generated android/build files. The overlay does not include or replace EOSG native binaries, export_presets.cfg, OTA scripts, audio scripts, or game RPC code.

GitHub Actions: add repository Actions secrets EOS_CLIENT_SECRET (rotate the exposed value before public release) and EOS_ENCRYPTION_KEY (64 hex characters). The workflow uses both to generate the ignored local config and applies the EOSG source shim before Godot imports the project.

Android template note: if android/build does not exist, the Android build template has not been installed. The resulting missing-Manifest message is expected until the template is installed; it is not a manifest-content error.
