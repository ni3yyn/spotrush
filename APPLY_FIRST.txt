SpotRush EOS Windows platform diagnostics patch

Overlay these files on your project root, keeping your existing 94 MB addons directory:
- scripts/networking/EOSOnline.gd
- addons/epic-online-services-godot/heos/hplatform.gd
- tools/fix_eos_autoload_comment.py

Then:
1. Close Godot.
2. Run from the SpotRush project root:
   python tools/fix_eos_autoload_comment.py
3. Reopen Godot, run the game, and click Create Room once.
4. Copy Output lines beginning with [EOS SDK], [HPlatform], or "EOS setup failed".

This patch does not print Product/Sandbox/Deployment IDs, Client ID, Client Secret,
or Encryption Key. Do not paste EOSLocalConfig.gd or any secret into chat.

The patch:
- exposes the exact EOS SDK Initialize result / stage;
- enables verbose EOS SDK logs before Platform Create;
- surfaces native EOS log messages through EOSOnline;
- fixes EOSG HPlatform's handling of EOS.Result.AlreadyConfigured;
- stops trying to format PlatformInterface.create()'s bool as an EOS.Result;
- provides a small helper to change accidental '#' pseudo-comment lines in the
  [autoload] section into valid ';' comments.

Godot 4.7.2 compile/export and actual EOS initialization still need to be tested
in the user's Windows editor. The Windows platform Create result is a bool in
EOSG 2.3.1; the verbose EOS SDK log is needed to identify the native reason if it
returns false.
